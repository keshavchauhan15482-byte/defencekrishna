# Hosted defence boundary — 25 November 2026

Public Vercel routes have an explicit positive schema. The hosted adapter now
also calls the historical passive DetectionEngine on inputs already rejected by
that schema, in disposable bounded workers with no deployment environment,
operator secrets, training memory, network replay or automatic mutation.
Existing bounded signatures remain authoritative for their known cases.
Worker unavailability never permits malformed inputs. The private proxy and
research fixtures are not deployed as internet-facing services.

Sudarshana supports opt-in, exact API-route/client-IP containment on the
canonical production hostname using two distinct Ed25519 operator approvals
over one serialized policy payload, confirmed-escape evidence reference,
a maximum 900-second lifetime and an emergency-stop override. A valid
platform-forwarded IP is required. A disabled, absent, expired or invalid
policy never creates a lock. This is a deployment-environment snapshot
verifier, not a live policy distribution service or a site-wide IP firewall.
No public request or Garuda forecast can sign/publish a policy. Never reuse
an operator signing private key in Vercel or commit it to source control.
Tests generate ephemeral keys and reserved documentation IPs only.
Live activation needs separately approved operator keys/policy provisioning,
a durable revocation/distribution mechanism and independent safety assessment.

Garuda remains advisory: current packet captures do not establish calibrated
host attribution to public HTTP clients. Prediction-to-lockdown requires
validated target binding, supported calibrated forecast evidence, explicit
operator policy and a measured false-positive budget. No automatic IP bans
or unsupported predictions are presented as prevention.

Vercel custom edge rules may reject requests before the application runs;
those denials are edge denials, not historical-engine detections. Managed
OWASP rule availability is plan-dependent. No paid services are activated here.
