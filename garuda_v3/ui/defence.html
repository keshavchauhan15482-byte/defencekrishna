GARUDA DEFENCE SYSTEM

Prediction first. Response with boundaries.

The defence layer separates predictive intelligence from reviewed memory and scoped containment. The runtime does not treat every high score as proof of attacker identity or an automatic licence to block.

G

Garuda

Garuda is the predictive layer. It receives the observed graph, returns the forward risk trajectory, attaches model provenance and explanation metadata, and emits the defence signal consumed by the response coordinator.

A

Arjuna

Arjuna represents the reviewed known-threat path. An exact graph fingerprint match in approved threat memory can route an event through Arjuna. That memory is distinct from an unreviewed model alert.

K

Krishna

Krishna receives unfamiliar forecast alerts. Pending events remain review candidates until an operator supplies an attack classification and evidence reference, after which the exact fingerprint can be promoted to reviewed memory.

S

Sudarshana

Sudarshana is the scoped containment / escalation path. Target scope is operator-selected; the model does not invent attacker IP attribution. Enforcement depends on runtime configuration, signing material and allowed network scope.

Review before memory

Only alert candidates can be approved into threat memory, and approval requires an attack type plus an evidence reference.

Lab automation is explicit

Automatic policy publication requires lab automation and enforcement to be enabled at startup, with a signing key and an allowed target scope.

Emergency control

The operator console exposes disarm, policy revoke and emergency revoke controls so the response path remains interruptible.
