GARUDA EVIDENCE

Measured results with claim boundaries intact.

The project keeps model evidence separate from presentation. The homepage loads benchmark values from stored run artifacts instead of shipping decorative accuracy numbers, and runtime forecasts preserve their source and model provenance.

01

Matched-run summaries

The benchmark API summarizes the stored logistic-regression, LSTM and GNN+LSTM runs using the same split boundaries, sources and prediction target before combining results.

02

Multi-seed reporting

The summary exposes mean and sample standard deviation across the stored initialization seeds. The UI keeps the scope statement visible rather than treating repeated seeds as independent datasets.

03

Persistence baseline

The evidence view includes the stored state-persistence MSE so learned state forecasting can be compared against a simple next-state-equals-current-state baseline.

04

Provenance

The active inference service verifies checkpoint integrity, returns a model SHA-256 in each forecast and carries the observation source into the response shown by the live console.

Validation-only thresholds

The stored benchmark contract treats threshold selection and calibration as validation-side operations rather than tuning against the final reported test rows.

Forecast withholding

If the observed graph is outside model support or incompatible with the trained checkpoint, the runtime can withhold inference instead of manufacturing a confident result.

Live evidence location

Use the homepage live console to load the current benchmark table, forecast provenance, observed graph, risk trajectory and response ledger from the local runtime.
