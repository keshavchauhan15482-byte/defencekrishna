GARUDA AI PLATFORM

From observed signals to what comes next.

The platform is built around a simple contract: preserve the observed network state, forecast its future trajectory, expose the evidence behind the signal, then route response through explicit authorization and review boundaries.

01

Observe

The local runtime accepts recorded graph replays or a user-supplied CSV / classic PCAP capture. The converter builds the graph history required by the active checkpoint and preserves the source label used by the UI.

02

Forecast

Garuda converts the validated graph history into a forward trajectory of malicious-flow scores and future state estimates. The live homepage renders that trajectory in the working risk meter and chart.

03

Explain

The current inference service can return feature attribution based on gradient × input sensitivity. The UI labels it as explanatory local sensitivity rather than causal proof.

04

Route

Forecast signals are passed to the response coordinator. Reviewed exact-memory matches route to Arjuna, unfamiliar alerts route to Krishna, and scoped containment is handled through Sudarshana authority gates.

Data source stays visible

The runtime distinguishes recorded replay from uploaded observations. The homepage never labels recorded demo input as a connected customer sensor.

Fail-closed inference

Schema, graph dimensions, continuity, finite values, model-support checks and checkpoint integrity are validated before the service returns a forecast.

Operator authority

Viewer access can inspect state. Policy creation, review approval, escalation and lab arming are operator-only actions.
